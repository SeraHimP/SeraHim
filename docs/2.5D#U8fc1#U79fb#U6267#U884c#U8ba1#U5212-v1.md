# 2.5D 迁移执行计划 v1

目标形态：LOL 式倾斜摄像机 + Three.js 3D 场景 + 2D Billboard Sprite 单位。
本计划基于对当前源码（~v40，22 套测试）的实际核查，修正了原可行性报告的三处问题，并重排了步骤顺序。计划日期 2026-07-22。

---

## 0. 前提与基线声明

- 当前 6 套测试失败（sim_v24×3 / sim_v39×2 / sim_v40×1 / sim_weather×2 / sim_wall×1 / sim_boot×1）。按你的决定**暂时忽略**，但迁移期间的回归判定基准是"不新增失败"，即每步交付后 `run_all.mjs` 的失败集合必须与当前完全一致，多一个都算迁移引入的回归。
- sim_boot 的 TDZ 失败已确认为误报（扫描器把 main.js 第 750-751 行注释里的 SIM_DT/MAX_SUBSTEPS 当成了代码）。
- src/ 下有 3 个 .bak 文件（main.js.bak、CollisionSystem.js.bak、LaneMovementSystem.js.bak），迁移不动它们，但建议在某个版本清掉。

## 对原报告的三处修正

| # | 原报告说法 | 实际情况 | 影响 |
|---|---|---|---|
| 1 | 天气视觉效果"直接写在 CanvasRenderer 里"，迁移时换成 Three.js 实现 | CanvasRenderer 里**没有任何天气渲染代码**，天气目前只有逻辑权重 + 设置面板 | 天气视觉是**新功能**不是移植，移出主线，放到最后可选步骤 |
| 2 | 第3步把 THREE.Sprite 挂到 `entity._sprite3d` | 违反"实体纯数据"原则，污染逻辑层、可能干扰测试序列化 | 改为 renderer 内部维护 `Map<entityId, THREE.Sprite>` |
| 3 | 交互迁移（raycasting 点选、拖拽）放在第5步"移除 Canvas"里顺带做 | 交互必须在删 Canvas **之前**完成并验证，否则中间存在一个无法操作的版本 | 交互独立成第4步，删 Canvas 后移为第5步 |

另有一处优化：原报告第2步用 TubeGeometry 重建道路（2-3天）。改为**复用 `_terrainLayer()` 现成离屏画布 → THREE.CanvasTexture 贴地面 plane**，视觉 1:1，成本降到半天。真几何体（墙体挤出高度等）作为后续增量。

注意：地图数据里墙体**不是现成多边形坐标**——可行走区域 = 走廊（waypoints ± corridorHalfWidth 130）∪ 基地圈（半径 1185），墙是这个区域的补集。所以"几何体墙"需要先生成补集网格，这也是贴图方案先行的另一个理由。

## 1. 目标架构（迁移完成后）

```
stepSimulation(dt)          ← 不变，16 个系统零改动
    ↓ 唯一调用边界
ThreeRenderer.render()      ← 新，读实体数据 → 更新 sprite/mesh
    ├─ TerrainBuilder       地面（贴图 plane，后续可换几何体）
    ├─ SpriteFactory        单位纹理工厂（复用 _getSprite 绘制逻辑）
    ├─ spriteMap            Map<entityId, THREE.Sprite>（渲染态不进实体）
    └─ 血条                 sprite 顶部小 canvas 纹理条
ThreeCameraController       ← 新，替代 CanvasController
    ├─ 拖拽平移 / 滚轮缩放（正交摄像机，zoom 语义与现在一致）
    └─ raycasting 点选 → onSelect(id) → uiManager.selectEntity(id)（复用现有链路）
UI 层（DOM）                ← 完全不动
```

摄像机选型：**先正交（OrthographicCamera）后透视**。正交下 zoom 就是缩放系数，与现有 CanvasController 的 zoom/offset 语义 1:1 映射，"重置视角适配全图"的逻辑可直接照搬；透视摄像机（更接近真 LOL）作为第6步可选增强，届时只改 Controller。

three.js 引入方式：**下载 three.module.js 放进 vendor/ 目录本地引用**，不走 CDN。理由：项目是零依赖单机页面，CDN 引入外部运行时依赖（断网/被墙即白屏），与"降级回退"原则冲突。

## 2. 分步计划

每步交付物 = 代码 + 验收清单 + 回退说明。每步结束跑 `run_all.mjs` 确认失败集合无变化，并手动过一遍运行时冒烟点。第1-4步全程保持双渲染（Canvas 照常工作，Three 叠加验证），任何一步出问题即时回退。

### 第1步：脚手架 + 双渲染（1 个会话）

**做什么**：Three.js 空场景跑起来，与现有游戏循环并行。

- 新增 `vendor/three.module.js`（本地化）
- 新增 `src/presentation/ThreeRenderer.js`：Scene / WebGLRenderer / OrthographicCamera（45° 俯角），`render()` 只清屏
- 改 `index.html`：加一个 `<canvas id="glCanvas">` 叠在现有 canvas 下层（或并排调试模式）
- 改 `src/main.js`：游戏循环里 `renderer.render()` 后追加 `renderer3d.render()`，加一个开关变量控制 Three 层显隐

**验收**：页面正常，控制台无报错；关掉 Three 层游戏与现在完全一致；测试失败集合不变。
**回退**：开关置 false 即回到纯 Canvas。

### 第2步：地面贴图 + 摄像机映射（1 个会话）

**做什么**：3D 世界里出现地图，摄像机能动。

- 新增 `src/presentation/TerrainBuilder.js`：取 `CanvasRenderer._terrainLayer(map)` 的离屏画布 → `THREE.CanvasTexture` → 贴到 `PlaneGeometry(world.w, world.h)` 上，平铺在 y=0
- `_terrainLayer` 的绘制逻辑抽成两者共享的独立函数（避免 Three 依赖 CanvasRenderer 实例）
- ThreeRenderer 监听 `map:loaded`，切图时重建贴图
- CanvasController 的 zoom/offset 变化同步映射到 Three 摄像机（临时桥接，第4步换掉）

**验收**：45° 视角下看到与 2D 版一致的地图；拖拽/缩放两个视图同步动；切图正确重建。
**回退**：同第1步开关。

### 第3步：单位 Billboard + 血条（1-2 个会话）

**做什么**：所有单位立进 3D 场景。

- 新增 `src/presentation/SpriteFactory.js`：复用 `_getSprite`/`_minionSprite`/`_towerSprite` 的离屏绘制逻辑生成纹理，缓存 `Map<key, CanvasTexture>`（对应现有 `_spriteCache`）
- ThreeRenderer 内部维护 `spriteMap: Map<entityId, THREE.Sprite>`（**不挂实体**）：每帧遍历 `entities.getAll(true)`，无 sprite 则创建入场景，有则 `position.set(pos.x, 0, pos.y)`；每帧末对 spriteMap 里已死亡/移除的 id 做清理（监听 `entity:death` 事件 + 兜底扫描双保险）
- 血条：每个 sprite 上方一个 16×3 小 canvas 纹理条，HP 变化才重绘（脏标记，避免每帧重画纹理）
- 龙、水晶、防御塔等特殊实体逐类接入

**验收**：双渲染对比，每个单位 3D 位置与 2D 一致；出兵自动出现、死亡消失、无 sprite 泄漏（长跑 5 分钟 scene.children 数量稳定）；血条正确；帧率不低于纯 Canvas 版。
**回退**：开关。

### 第4步：交互迁移（1 个会话）

**做什么**：操作从 Canvas 坐标系换到 3D，这是删 Canvas 的前置条件。

- 新增 `src/presentation/ThreeCameraController.js`：拖拽平移（XZ 平面）、滚轮缩放（camera.zoom，范围沿用 0.15-3.0）、重置视角适配全图（移植现有 fit 逻辑）
- 点选：raycaster 打 sprite → 命中取 entityId → 调用与现在相同的 `onSelect(id)` 链路；命中判定要复现现有的 slack 容差手感（小单位难点中的问题）
- 保留现有 zoomIn/zoomOut/reset 按钮绑定，只换实现

**验收**：Canvas 层隐藏状态下，点选/拖拽/缩放/重置全部正常，选中单位面板正确弹出；zoom 标签显示正确。
**回退**：切回 CanvasController + 显示 Canvas 层。

### 第5步：摘除 Canvas 渲染（0.5 个会话）

**做什么**：Three 成为唯一渲染器。

- main.js 移除 CanvasRenderer/CanvasController 引用（文件保留在仓库，只断引用）
- index.html 移除 2D canvas 元素或隐藏
- SpriteFactory / TerrainBuilder 确认不再依赖 CanvasRenderer 实例（第2步已抽离）

**验收**：全功能手动过一遍（沙盒、对战、切图、编辑器、设置面板、天气面板）；`run_all.mjs` 失败集合不变；性能不劣化。
**回退**：恢复引用即回到双渲染。

### 第6步：可选增强（按需、逐项独立）

优先级建议排序：

1. **墙体挤出高度**——生成"走廊补集"网格并挤出，高地/墙第一次有真实体积，视觉收益最大
2. 透视摄像机（真 LOL 视角）
3. 天气视觉（**新功能**）：scene.fog、DirectionalLight 日夜、Points 粒子雨雪，读现有 weatherState
4. 死亡/攻击粒子、bloom 后处理
5. 建筑占位换免费 3D 模型

## 3. 工作量与交付方式

| 步骤 | 会话数 | 新文件 | 改动文件 |
|---|---|---|---|
| 1 脚手架 | 1 | ThreeRenderer.js, vendor/three.module.js | main.js, index.html |
| 2 地面 | 1 | TerrainBuilder.js | ThreeRenderer.js, CanvasRenderer.js（抽函数） |
| 3 单位 | 1-2 | SpriteFactory.js | ThreeRenderer.js |
| 4 交互 | 1 | ThreeCameraController.js | main.js |
| 5 摘除 | 0.5 | — | main.js, index.html |
| **主线合计** | **4.5-5.5** | 4 个 | 3 个 |

按既有工作模式：每步一次交付，附验收清单；触到用量上限就出 handoff checklist 交接。逻辑层（systems/、core/、data/）全程零改动，任何一步发现需要改逻辑层即停下来先确认。

## 4. 风险清单

| 风险 | 应对 |
|---|---|
| 迁移中新增测试失败被现有 6 个失败掩盖 | 每步交付记录失败集合快照，逐条比对 |
| raycasting 点选手感与现有 slack 容差不一致 | 第4步单独验收，必要时给 sprite 加不可见的放大命中区 |
| CanvasTexture 血条每帧重绘拖慢帧率 | 脏标记 + 只在 HP 变化时更新纹理 |
| sprite 泄漏（死亡单位残留） | 事件清理 + 每帧兜底扫描双保险，长跑验收 |
| 切图/重开局时场景残留 | map:loaded 时整体 dispose 重建，纹理缓存显式释放 |
| WebGL 上下文丢失（移动端/长时间运行） | 监听 contextlost，提示刷新（不做自动恢复，成本不值） |
