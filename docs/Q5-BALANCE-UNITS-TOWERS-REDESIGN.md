## 一、数值修复类（已定方案，待实现）

### 1.1 枢纽塔太弱（诊断完成，方案已定）

**症状**：用户反馈枢纽双塔（hq_tower）/水晶塔（base，都装闪电杖）伤害弱。

**根因排查**：不是 `CONFIG.tuning.adaptiveDamage.apMagicDamagePct=60%` 那条全局自适应折扣——
闪电杖是 `specialAttack` 武器，`CombatSystem.performAttack` 第613行命中就直接 `return`，
完全跳过普通攻击管线，伤害只来自闪电杖自己的 `_doTick`：`20%×AP×充能倍率`，每秒固定4跳、
和攻速脱钩。同样的原始数值，闪电杖的产出量级只有假想同数值物理塔（AD×攻速4.0）的两三成，
这才是偏弱的根因。

**方案**：`CONFIG.tuning.weapons.lightningApConvertPct`（AD→AP转化率，当前100%即1:1）调到
**200%**。已软编码，改一个数字即可，塔的初始AP和AP成长（`towerGrowth.apRatioOfAd`）同步放大。

### 1.2 风魂重做（已定稿："疾风连击"）

**问题**：现状是"小兵脱战+移速/塔+攻速"两截。用户实测指出更本质的问题——龙魂只发给
塔+大型小兵（`DragonSystem.SOUL_REWARD_OK` 排除近战/远程），"全体小兵移速"这个描述本身
是假的：一条兵线里只有图腾/术士/炮车这些大型小兵会提速，近战/远程原地不动，一队兵被硬生生
拆成两拨，**反而比不拿风魂更容易被各个击破**。

**定稿方案**："疾风连击"——命中一次目标，获得一层疾风，`bonusAttackSpeedPct` 每层 +8%，
最多5层（封顶+40%），走 `stackPolicy:'stack'`（EffectRegistry 原生支持：自动+1层、刷新
duration，不需要自己额外维护计数器，参考 `EffectRegistry.js` 177-196行）；`duration` 设为
3秒，3秒内没有新的命中则整层清空。塔与大型小兵共用同一套机制，不再分"塔一半/小兵一半"。
这是 `bonusAttackSpeedPct`，会自动走 `attackSpeedRatio` 收益率（`calcAttackSpeedOf` 公式：
`effectiveBonusPct = positive×attackSpeedRatio + negative`），用户已确认这就是"走收益率"的
意思，不需要额外处理。

原有 `towerBonusAttackSpeedPct: 35`（常驻攻速）、`moveSpeedPct`/`moveSpeedOutPct`（移速）
两截全部删除。`CONFIG.gameRules.dragonSouls.wind` 改成 `{ perStackPct: 8, maxStacks: 5,
decaySec: 3 }`。

### 1.3 术士兵/图腾兵/攻城车削弱 + 收窄定位（已定方向，具体数值待定）

**发现的结构性问题**：术士兵主动技能"蓄能打击"自身法强永久无上限叠加
（`maxStacks:999`，每次+5，事实上不封顶）——这可能是"术士兵太强"被低估的一块，
一个能存活的术士兵会无限膨胀，需要加上限。

**收窄方向（见第三节，与新兵种方案一起定稿）**：
- 图腾兵收窄成**只做"光环治疗"**：主动技能改常驻光环持续回复，去掉减伤光环和额外护盾光环，
  自身固定护盾保留（"扛线"天然定位）
- 术士兵收窄成**只做"光环增伤"**：只留一条光环数值，穿透/法强/自身叠层全部删除
- 蚀骨兵：相对已经单一（近战AOE削双抗+主动中毒），只做数值上的小削弱，不改方向
- 攻城车：对塔伤害倍率700%→约550%，攻城疲惫每次攻击叠层13→16（更快自我降速）

### 1.4 超级兵早弱晚强（已定方案）

现状：超级兵数值是常量，不随游戏时间变化，"水晶陷落后立刻满状态出场"是提前终结比赛的漏洞。

**方案**：新增被动技能，在超级兵**生成那一刻**按当前游戏时间快照一个 `allStatsPct` 修正——
游戏时间≤0min 时基础数值打4折，线性爬升到15分钟满状态（100%），15分钟后继续缓慢增长
（每分钟再多约1.5%，上限150%封顶）。倍率在出生那一刻定死，不随单位存活时间变化。

## 二、新发现的bug（待排查，先记录）

1. **闪电杖对带"伤害格挡"（damageBlock）的目标格挡失效**——闪电杖伤害走
   `performAttackDirect` 直接传入已算好的数值，`CombatSystem.js` 1573行那处格挡扣减逻辑
   可能没覆盖这条路径，需要对着代码确认根因。

2. **天气：雪盖视觉阈值突变**——积雪到某个阈值后地面直接变白，很突兀，应该是缓慢过渡到白色，
   不是硬切换。（`GroundTraceLayer.js` 的雪盖 alphaMap 渲染，或 `GroundTraceSystem.js` 的
   `snowGlobalTarget`/局部雪深插值逻辑，需要排查是不是哪里用了阶跃而不是渐变）

3. **兵踩出的轨迹机制用户没看懂**——雪盖的"单位经过局部踩低、留下比周围雪盖更浅的小径"这个
   效果，用户反馈目前没看明白/没看到，需要排查是真的没生效还是视觉上不明显。

4. **水洼状态常驻bug**——下雨时单位身上常驻着"水洼"减速状态，这是错的：应该只有单位【站在】
   水洼区域内时才有这个状态和移速降低，离开水洼就该消失。需要排查 `GroundTraceSystem.js`
   `_applyEffects()` 里水洼判定逻辑，可能是位置判定漏了或者判反了。

## 三、新兵种方案（讨论中，未最终定稿，暂不实现）

设计前提（用户反复强调）：单位不做决策，只会机械攻击/触发——任何新机制都必须能落在
"命中触发/周期触发/阈值触发"这三种既有模式里，不能要求"选择目标/评估局势"这类决策。

### 3.1 重装车 / 龟甲车（命名待定，倾向"龟甲车"）

**定位**：塔攻击优先级最高的坦克。略高血量、超高双抗、自带伤害格挡；攻速极低、攻击力一般
（对塔有额外伤害，但要比攻城车温和得多——只是坦着打的副产物，不能抢攻城车的戏）。
主动技能：一段时间内获得伤害减免。

**待实现要点**：需要在 `CombatSystem.selectTarget` 里给这个类型加最高优先级权重，
与3.3工程兵的"塔保护工程兵"是同一套目标优先级逻辑，两者要放一起设计优先级顺序（互不冲突）。

命名备选：龟甲车（慢、硬壳、挨打为生，形象最直接）／铁壁兵／岩卫兵。

### 3.2 治疗兵

**定位**：无攻击敌方能力，按攻速节奏对友军造成治疗（不是主动技能触发，是类似"攻击"的
固定节奏脉冲），每次治疗损失固定生命值+百分比当前生命值（自我消耗换奶）；脱战后拥有
高额生命恢复（换血的恢复窗口）。

**架构要求（用户明确提出，不能走捷径）**：用户后续还计划做一座"没有攻击能力、专职给友军
回血的塔"，所以"单位的攻击目标指向友方而不是敌方"必须做成底层架构的一个"目标阵营"开关，
不是治疗兵一个人的特例代码——现在全局都是写死"只认敌方"（`FactionSystem.enemyUnitsInRadius`
这类）。治疗兵和以后那座奶塔要共用同一套东西，包括专属的"治疗弹道"可视化（攻击特效目前
按武器/技能各自定义子弹外观，加一个治疗方向的弹道素材配上这个开关即可，不用另搭一套）。

### 3.3 工程兵

**定位**：无攻击能力，修复己方防御塔生命值；且能以33%效率**突破"加固城防"的节点封顶**
去修复超出节点的部分；己方防御塔被攻击工程兵的单位命中后立即切目标优先攻击那个单位
（保护工程兵）。

**已确认的技术路径**：全部塔默认自带"加固城防"节点封顶（`towerPassives.js`
`_fortifyRecalc`，节点数组如水晶塔33/67/100%——当前血量卡在哪个区间，恢复就只能封顶到那个
区间上界，越不过去）。现在所有治疗来源统一走 `applyHeal(entity, amount, healPower, maxHP,
capHP)`，`capHP` 传的就是 `entity._regenCapHP`。工程兵要做的是**调用治疗时不传这个cap**，
超出节点部分单独按33%效率结算——不用碰治疗管线本身，只是工程兵自己的调用方式跟别的
治疗源不一样。

"塔保护工程兵"与3.1重装车共用同一套目标优先级扩展，需要一起设计顺序。

### 3.4 唤灵兵（用户最喜欢这个，已有较完整方案）

**定位**：唯一一个"凭空多一个打架的身体"而不是"加成数值"的兵种。

**机制**：主动技能走现有法力槽架构（跟图腾/术士的主动技能同一套），法力攒满时在自己脚下
召唤一只幻灵——一个真正的小型战斗单位（复用现有小兵创建管线，不是特效摆设），存在
12~15秒后自动消失（或提前被打死）。唤灵兵自己血/攻偏低，指望幻灵抗线。

**幻灵具体设计**：
- 血量/攻击力取偏低量级（近战兵的60~70%），不成长，纯粹"临时补人头"
- 同时最多存在2只（软编码上限，防止无限叠加）
- 幻灵不计入屠戮/龙魂奖励/出兵编排统计口径（打 `_isSummoned` 标记排除）
- 视觉：半透明+灵体粒子，一眼看出是召唤物

**平衡杠杆（软编码）**：法力槽大小（召唤间隔）、幻灵存活时长、幻灵强度、同时存在上限。

## 四、云顶之弈式"羁绊"系统——已明确推迟，这轮不做

用户认可这个方向（"这不是自走棋吗"），但明确说"羁绊先记下来，这轮不做"。

**思路记录**：给每个兵种打1-2个流派标签，战场上同时存活的某标签兵种数量达到阈值
（比如2/4档）时，全体带该标签的单位一起获得一档加成——云顶"集齐N个羁绊解锁效果"的思路。
比新增单个兵种的工作量大得多（要给所有兵种打标签、实时数数、分档加成），下一轮再单独立项。

## 五、塔的多样化方案（初版4个，用户要求"再想想"，见后续对话补充）

现状：塔只有穿透（物理双穿+升温，稳定输出）和闪电杖（法术DoT+减益，稳定输出）两条路，
手感高度同质。初版4个新方向：

1. **寒冰锥**——攻击范围减速+破甲，塔第一次有AOE控场武器
2. **汲取**——伤害按比例转化成自身护盾，塔第一次有"打人回血"的生存型武器
3. **连弩**——攻击有概率触发一次额外瞬间攻击，爆发不稳定输出，跟另外两条"稳定DPS"手感不同
4. **驱散者**——攻击附带清除目标一个正面状态，第一次有"反制/去buff"而不是纯造成伤害的武器
